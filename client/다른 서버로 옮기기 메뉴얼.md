# 다른 서버에서 NAS 마운트 · 라벨링 GUI 운영하기

지금은 10.254.92.108 서버(이하 **108 서버**)가 NAS를 마운트하고 라벨링 GUI를 띄운다.
이 문서는 같은 일을 다른 서버(이하 **새 서버**)에서 하도록 옮기는 절차다.

---

## 0. 먼저 알아 둘 것 — 라벨은 NAS가 아니라 GUI 서버에 저장된다

| 무엇 | 어디에 있나 | 서버를 옮길 때 |
|---|---|---|
| 영상(청크 zip), 메타데이터 | NAS (`/mnt/nas/...`) | 새 서버에서 마운트만 하면 됨 |
| 라벨, 수정 이력, 청크 분배 | GUI 서버의 `Nvidia-VLM/nas_labels/<데이터셋>/` | **직접 복사해야 함** |
| 라벨러 계정(비밀번호 해시) | GUI 서버의 `nas_labels/users.json` (git 제외) | **직접 복사해야 함** |
| 로그인 세션 | GUI 서버의 `nas_labels/sessions.json` (git 제외) | 복사 안 하면 모두 다시 로그인 |

그래서 아래 두 가지를 반드시 지킨다.

- **GUI는 한 번에 한 서버에서만 띄운다.** 두 서버에서 동시에 라벨링하면 라벨 파일이 두 벌로 갈라지고, 나중에 합칠 방법이 없다.
- **옮길 때는 순서를 지킨다.** 기존 서버 GUI 종료 → `nas_labels/` 복사 → 새 서버 GUI 실행.

## 1. 새 서버 준비 (최초 1회)

### 1-1. 코드 가져오기

```bash
# git 으로
git clone <저장소 주소> ~/Jeongbin/Nvidia-VLM

# 또는 108 서버에서 통째로 복사 (results/ 등 큰 폴더는 빼도 된다)
rsync -a --exclude results/ --exclude pav_sample/ --exclude .cache/ \
  -e "ssh -p 1024" etri@10.254.92.108:/home/etri/Jeongbin/Nvidia-VLM/ ~/Jeongbin/Nvidia-VLM/
```

폴더 위치는 어디든 된다. 다만 108 서버와 다르면 **5장**에서 클라이언트의 `REMOTE_DIR`을 바꿔야 한다.

### 1-2. Python

GUI(`gui_server.py`)와 라벨링(`nas_labeling.py`)은 **표준 라이브러리만** 쓴다.
conda 환경이나 GPU는 필요 없고, `python3` 3.9 이상이면 된다(108 서버는 3.12).

클라이언트 실행파일은 SSH로 접속해 `python3`를 그대로 부른다. 그래서
**비대화형 SSH에서 잡히는 `python3`**의 버전을 확인해 둔다.

```bash
ssh -p <SSH포트> <계정>@<새서버> "which python3; python3 --version"
```

### 1-3. NAS 마운트 도구

```bash
sudo apt install cifs-utils     # mount -t cifs 에 필요
sudo mkdir -p /mnt/nas
```

## 2. NAS 마운트

```bash
sudo mount -t cifs //10.254.92.171/OPEN_DATASET /mnt/nas \
  -o username=E2E_DATA,vers=3.0,uid=$(id -u),gid=$(id -g),cache=loose,nounix,serverino,iocharset=utf8
```

NAS 비밀번호를 묻는다. 마운트가 됐는지는 이렇게 확인한다.

```bash
ls /mnt/nas/NVIDIA_DATASET/20260901/camera     # camera_front_wide_120fov 가 보이면 정상
ls /mnt/nas/NAVSIM/20261105/camera             # NavSim 데이터셋을 쓸 때
```

- **마운트 위치는 `/mnt/nas`를 권장한다.** 코드가 이 경로를 기준으로 되어 있다
  (`clip_source.py`의 `NAS_CAMERA_DIR`, `nas_datasets.json`의 `mounts`).
  다른 경로에 마운트하려면 이 두 곳을 같이 고쳐야 한다.
- **재부팅하면 마운트가 풀린다.** fstab 자동 마운트는 NAS 비밀번호를 파일에
  저장해야 해서 일부러 쓰지 않는다. 재부팅 후에는 이 명령을 다시 실행하고
  GUI도 재시작한다(4장).
- 새 서버가 NAS(10.254.92.171)에 닿는 망에 있어야 한다. 마운트가 시간 초과로
  실패하면 `ping 10.254.92.171`부터 확인한다.

## 3. 라벨 옮기기

### 3-1. 108 서버의 GUI 끄기 (먼저!)

```bash
ssh -p 1024 etri@10.254.92.108 "pkill -f gui_server.py"
```

끄지 않고 복사하면, 복사하는 동안 저장된 라벨이 새 서버에 빠진다.
라벨러들에게 미리 작업을 멈추라고 알린다.

### 3-2. `nas_labels/` 통째로 복사 (새 서버에서 실행)

```bash
cd ~/Jeongbin/Nvidia-VLM
rsync -a -e "ssh -p 1024" \
  etri@10.254.92.108:/home/etri/Jeongbin/Nvidia-VLM/nas_labels/ ./nas_labels/
```

`users.json`(계정)과 `sessions.json`(로그인)도 함께 옮겨진다.
git으로 코드를 받았어도 이 두 파일은 git에 없으므로 **반드시 이 복사를 한다**.

### 3-3. 복사 확인

두 서버에서 같은 숫자가 나와야 한다.

```bash
wc -l nas_labels/*/history.jsonl
python3 nas_labeling.py users          # 계정 목록
```

라벨의 정본은 `history.jsonl`(수정 이력)이다. GUI를 띄울 때 이력으로 `labels.json`을
다시 만들어 맞춘다. 그래서 이력 파일 줄 수만 같으면 라벨도 같다.

### (참고) 라벨 없이 새로 시작하는 경우

```bash
python3 nas_labeling.py useradd <아이디> --name <표시이름> --admin   # 첫 관리자
```

## 4. GUI 실행

```bash
cd ~/Jeongbin/Nvidia-VLM
setsid nohup python3 gui_server.py --port 8000 --data nas >> gui.log 2>&1 &
```

확인:

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/    # 200 이면 정상
tail -20 gui.log
```

- **`--host 0.0.0.0`은 쓰지 않는다.** GUI에는 인증이 없고, 서버에서 학습·추론
  스크립트를 실행하는 기능이 있다. 기본값(127.0.0.1)으로 두고 SSH 터널로만 접속한다.
- 처음 띄울 때 NAS의 영상 인덱스(`.clip_index.json`)를 읽는다. 이 파일은 NAS에
  있어 서버끼리 같이 쓰므로, 108 서버에서 이미 만들어 둔 것을 그대로 읽는다.
- 새 서버에서 추론까지 돌리려면 conda 환경과 GPU가 따로 필요하다. 이 문서는
  GUI와 라벨링까지만 다룬다.

## 5. 클라이언트(라벨러 PC) 설정 바꾸기

이 `client/` 폴더의 기본값은 108 서버를 가리킨다. 새 서버에 맞게 바꿔서
라벨러들에게 다시 나눠 준다.

| 항목 | 지금 값 | 새 서버에 맞게 |
|---|---|---|
| 서버 주소 | `10.254.92.108` | 새 서버 IP |
| 계정 | `etri` | 새 서버 SSH 계정 |
| SSH 포트 | `1024` | 새 서버의 sshd 포트 (보통 `22`) |
| 코드 위치 | `/home/etri/Jeongbin/Nvidia-VLM` | 1-1에서 받은 경로 |

### Windows — `GUI-접속.bat` 상단

```bat
set "USER=etri"
set "SERVER=10.254.92.108"
set "REMOTE_DIR=/home/etri/Jeongbin/Nvidia-VLM"
set "SSH_PORT=1024"
```

### Linux / macOS — `gui-connect.sh`

파일을 고쳐도 되고, 실행할 때 환경변수로 덮어써도 된다.

```bash
USER_NAME=<계정> SERVER=<새서버IP> SSH_PORT=22 \
REMOTE_DIR=/home/<계정>/Jeongbin/Nvidia-VLM ./gui-connect.sh
```

### `gui-doctor.sh` (서버 쪽, 선택)

`gui-doctor.sh`는 실행에는 문제가 없다. 다만 오류가 났을 때 보여 주는 안내 문구에
`10.254.92.108`과 포트 `1024`가 적혀 있다. 혼동을 막으려면 새 서버 값으로 바꾼다.

### SSH 키 다시 등록

새 서버에는 라벨러의 공개키가 없다. `README.md`의 "SSH 키 등록"을
**주소와 포트만 바꿔서** 한 번씩 다시 한다.

```bash
ssh-copy-id -p <SSH포트> <계정>@<새서버IP>
```

## 7. 다시 108 서버로 돌아갈 때

방향만 반대로 해서 3~5장을 똑같이 한다.

1. 새 서버 GUI 종료 (`pkill -f gui_server.py`)
2. 새 서버의 `nas_labels/`를 108 서버로 `rsync`
3. 108 서버에서 NAS 마운트 확인 후 GUI 실행
4. 클라이언트 설정을 원래 값으로 되돌림

라벨을 git에 커밋할 때도 **지금 GUI를 띄우고 있는 서버에서만** 커밋한다.
다른 서버의 오래된 `nas_labels/`를 커밋하면 최신 라벨을 덮어쓸 수 있다.

## 문제 해결

**`mount error(13): Permission denied`**
→ NAS 비밀번호가 틀렸거나 `username`이 다르다.

**`mount: unknown filesystem type 'cifs'`**
→ `sudo apt install cifs-utils`를 실행한다.

**GUI는 뜨는데 NAS 탭이 비어 있다**
→ GUI를 NAS 마운트보다 먼저 띄웠다. 마운트를 확인하고 GUI를 재시작한다.
GUI는 시작할 때 NAS 인덱스를 읽는다.

**로그인이 안 된다 / 계정이 없다고 나온다**
→ `users.json`이 복사되지 않았다. 3-2를 다시 하거나, `python3 nas_labeling.py users`로 계정 목록을 확인한다.

**라벨이 일부 빠져 보인다**
→ 108 서버 GUI를 끄기 전에 복사했을 가능성이 크다. 108 서버의 `history.jsonl`이
더 길면, 새 서버 GUI를 끄고 3-2부터 다시 한다.

**클라이언트가 `Connection refused`를 낸다**
→ `SSH_PORT`가 새 서버의 sshd 포트와 다르다. 108 서버는 1024였지만 새 서버는 보통 22다.
